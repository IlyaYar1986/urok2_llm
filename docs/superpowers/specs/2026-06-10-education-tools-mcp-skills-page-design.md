# Страница «Инструменты, MCP и Skills для образования»

## Цель

Создать отдельную HTML-страницу как практическое продолжение занятия
«Агентные системы». Страница должна объяснять преподавателям колледжей и
руководителям кружков по ИИ:

- чем отличаются инструмент, MCP и skill;
- как устроены MCP-сервер и Agent Skill;
- как создать их самостоятельно;
- какие готовые инструменты, MCP и skills полезны в образовательной работе;
- как объединять их в безопасные практические сценарии.

## Размещение и навигация

- Новый файл: `web/instrumenty_mcp_skills.html`.
- На странице должна быть ссылка назад на `web/agentnye_sistemy.html`.
- В `web/agentnye_sistemy.html` нужно добавить заметный переход к новой
  практической части.
- На главной странице `index.html` нужно добавить ссылку на продолжение рядом
  со ссылкой на занятие 2.
- Фиксированная горизонтальная навигация новой страницы ведёт к основным
  разделам и остаётся прокручиваемой на узких экранах.

## Визуальный язык

Страница продолжает существующий стиль лекции:

- светлый фон с мягкими радиальными градиентами;
- индиго как основной цвет, циан и зелёный как дополнительные акценты;
- шрифт `Segoe UI`, системные запасные шрифты;
- крупный заголовок, короткое вводное описание и кнопки перехода;
- белые карточки с тонкой рамкой, скруглением и мягкой тенью;
- оконные панели с тремя цветными точками для кода и схем;
- нумерованные секции и плавное появление элементов при прокрутке.

Страница должна выглядеть частью лекции, но быть самостоятельным справочником,
которым можно пользоваться после занятия.

## Структура страницы

### 1. Введение

Hero объясняет формулу:

`Инструмент выполняет действие → MCP даёт доступ → Skill задаёт методику`.

Также показывается маршрут страницы и две кнопки: начать с MCP и перейти к
готовым наборам.

### 2. MCP своими руками

Раздел включает:

- простое определение MCP;
- визуальную схему `ИИ-клиент → MCP-сервер → внешний сервис`;
- объяснение сущностей `tools`, `resources`, `prompts`;
- пример структуры проекта;
- последовательность создания MCP-сервера;
- правила выбора прав доступа.

Два уровня технической глубины:

- сразу виден минимальный псевдошаблон для начинающих;
- в раскрывающемся блоке находится полноценный пример на Python с FastMCP,
  зависимостями, запуском и конфигурацией клиента.

Рабочий пример должен быть безопасным учебным сервером, который читает
разрешённые методические файлы и создаёт план занятия без доступа ко всей
файловой системе.

### 3. Skill своими руками

Раздел включает:

- отличие skill от обычного промпта и MCP;
- схему загрузки: metadata → `SKILL.md` → scripts/references/assets;
- структуру папки skill;
- правила написания `name`, `description` и основной инструкции;
- рекомендации по триггерам, входным данным, шагам, результату и ограничениям.

Два уровня технической глубины:

- сразу виден короткий шаблон `SKILL.md`;
- в раскрывающемся блоке находится полный пример `lesson-designer` с
  последовательностью работы и форматом результата.

### 4. Инструменты преподавателя

Карточки группируются по задачам:

- подготовка и исследование: NotebookLM, ChatGPT/Claude/Gemini;
- практика: Google Colab, Kaggle;
- публикация проектов: Hugging Face Spaces, GitHub;
- материалы и контроль: Canva/Gamma, Kahoot/Quizizz/Forms;
- обучение и автоматизация: Stepik/Moodle, n8n/Make.

Каждая карточка отвечает на три вопроса:

- что это;
- для чего использовать;
- пример образовательного сценария.

### 5. Каталог MCP

В каталог входят:

- Filesystem;
- Google Drive;
- GitHub;
- Git;
- Fetch/Search;
- Playwright;
- PostgreSQL/SQLite;
- Memory;
- Calendar;
- Telegram/Slack;
- n8n;
- собственный Moodle/Stepik MCP.

Каждая карточка содержит назначение, пример запроса и рекомендуемый уровень
доступа: чтение, подтверждение записи или отдельная песочница.

### 6. Каталог Skills

Две группы:

- для преподавателя: `lesson-designer`, `assessment-builder`,
  `rubric-builder`, `assignment-differentiator`, `source-grounded-tutor`,
  `lab-work-generator`, `feedback-writer`, `fact-checking-teacher`,
  `student-progress-analyst`, `course-material-adapter`,
  `inclusive-material-reviewer`, `academic-integrity-reviewer`;
- для руководителя кружка: `ai-project-mentor`, `project-idea-generator`,
  `dataset-curator`, `prompt-lab`, `model-comparison`,
  `code-review-teacher`, `ml-experiment-designer`, `ai-ethics-reviewer`,
  `project-defense-coach`, `hackathon-organizer`,
  `student-portfolio-builder`.

Каждая карточка объясняет результат skill и показывает пример команды.

### 7. Готовые комплекты

Четыре пошаговых сценария:

- подготовка занятия;
- проверка студенческого проекта;
- организация работы кружка;
- проведение хакатона.

Для каждого сценария показывается связка:
`инструмент + MCP + skill → результат`.

### 8. Безопасный запуск

Финальный чек-лист:

- начинать с режима чтения;
- ограничивать доступ отдельной папкой или репозиторием;
- не передавать персональные данные и ключи;
- требовать подтверждение перед отправкой, публикацией и удалением;
- проверять источники, код и оценки человеком;
- тестировать сторонние MCP и skills в песочнице.

## Интерактивность

- Нативные `<details>` используются для технических примеров и длинных
  пояснений.
- Кнопка копирования добавляется к основным блокам кода.
- Навигация подсвечивает текущий раздел.
- `IntersectionObserver` включает плавное появление карточек.
- JavaScript не должен быть необходим для чтения основного содержания.

## Адаптивность и доступность

- На ширине до 900 px многоколоночные блоки становятся одноколоночными.
- На мобильных устройствах навигация прокручивается горизонтально.
- Контраст текста и элементов управления должен оставаться достаточным.
- У всех интерактивных элементов есть понятные подписи и состояния фокуса.
- Код не должен вызывать горизонтальную прокрутку всей страницы.
- При `prefers-reduced-motion` анимации отключаются.

## Проверка

- Проверить отсутствие горизонтального переполнения на 1440×900, 768×1024 и
  390×844.
- Проверить ссылки между новой страницей, занятием 2 и главной.
- Проверить открытие `<details>`, копирование кода и активную навигацию.
- Проверить отсутствие ошибок JavaScript в консоли.
- Запустить существующие тесты проекта и добавить точечную проверку новой
  страницы, если текущий тестовый подход это позволяет.
