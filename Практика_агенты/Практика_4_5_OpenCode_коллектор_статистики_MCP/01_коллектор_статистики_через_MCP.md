# Практика 4.5. Коллектор статистики через MCP

## Назначение файла

Эта инструкция нужна куратору для проведения практики 4.5.

Тема: создание в OpenCode агента для учета успеваемости и посещаемости, который не считает числа сам языковой моделью, а вызывает MCP-инструмент для чтения таблицы и расчета показателей.

Исходная задача из программы:

> Агент для учета успеваемости, посещаемости. Принимает текстовую или табличную выгрузку с данными студентов, считает средний балл, выявляет пропуски и формирует список группы риска. Выдает готовый отчет или уведомления без ручной обработки данных.

## Почему MCP показываем здесь

В практике 4.4 скрытую легенду из Google Doc было проще получить скриптом: одна ссылка, один файл, одно действие.

В 4.5 MCP уместнее:

- есть структурированные данные;
- есть точные расчеты;
- есть риск ошибок, если считать через LLM;
- агенту нужен отдельный инструмент, который возвращает проверяемый результат;
- в будущем источник можно заменить: CSV, Excel, Google Sheets, база данных.

Куратор объясняет:

> LLM хорошо понимает запрос и оформляет отчет. Но числа в ведомости должна считать не модель, а инструмент. MCP здесь нужен как граница между разговорным агентом и точной обработкой данных.

## Главная педагогическая идея

Участники должны увидеть три роли:

- `skill` или проектная инструкция - объясняет агенту, как работать с ведомостью;
- MCP-инструмент - читает данные и считает показатели;
- LLM - принимает запрос преподавателя, вызывает инструмент и оформляет понятный отчет.

Важно:

- не давать готовый MCP-код;
- сначала описать показатели;
- создать обезличенные учебные данные;
- попросить OpenCode спроектировать MCP;
- проверить расчеты руками на маленьком примере;
- только потом доверять отчету.

## Безопасность и персональные данные

Куратор обязательно проговаривает:

> В реальных ведомостях есть персональные данные. На занятии используем только обезличенные учебные данные: `student_id`, группа, оценки и пропуски. ФИО, телефоны, диагнозы, заявления и реальные причины отсутствия не используем.

Учебный набор данных должен быть синтетическим.

Если участники хотят использовать реальную таблицу колледжа:

- заменить ФИО на `student_id`;
- убрать телефоны, адреса, даты рождения;
- убрать медицинские и социальные подробности;
- не отправлять реальные данные во внешние API;
- для реального контура использовать локальную модель и локальные инструменты.

## Ожидаемый результат

К концу практики у участника есть проект:

```text
opencode-stat-collector/
  AGENTS.md
  data/
    group_stats.csv
  mcp/
    stat-collector/
      index.js
      package.json
      package-lock.json
      node_modules/
  outputs/
    report.md
  opencode.json
```

OpenCode получает запрос на естественном языке, вызывает MCP-инструмент и формирует отчет:

- средний балл по группе;
- количество пропусков;
- доля неуважительных пропусков;
- список студентов группы риска;
- краткие рекомендации куратору.

## Что именно создает OpenCode

Куратор после создания файлов делает отдельную паузу и разбирает структуру проекта.

Важно объяснить участникам:

> Мы создаем не один промпт, а маленькую агентную систему. В ней есть данные, правила поведения агента, MCP-инструмент для расчетов, конфигурация подключения и папка для отчетов.

### 1. `data/group_stats.csv`

Это учебная обезличенная таблица.

В ней должны быть строки студентов и колонки:

- `student_id` - обезличенный идентификатор студента, например `S001`;
- `group` - учебная группа;
- `avg_grade` - средний балл;
- `failed_subjects` - количество предметов с задолженностью;
- `absences_total` - общее количество пропусков;
- `absences_unexcused` - пропуски без уважительной причины;
- `assignments_missing` - количество несданных заданий.

Для чего нужен файл:

- дает агенту проверяемый источник данных;
- позволяет участникам увидеть, на каких данных строится отчет;
- помогает проверить MCP на маленьком наборе строк;
- показывает принцип обезличивания данных.

Что важно проверить:

- нет ФИО, телефонов, адресов и других персональных данных;
- все числовые поля действительно числа;
- есть несколько студентов группы риска;
- данных достаточно мало, чтобы куратор мог проверить результат глазами.

### 2. `AGENTS.md`

Это проектная инструкция для OpenCode.

В ней описано:

- роль агента: помощник куратора по статистике успеваемости и посещаемости;
- запрет считать показатели языковой моделью;
- требование использовать MCP-инструмент `stat-collector`;
- правила обезличивания;
- критерии группы риска;
- формат итогового отчета.

Для чего нужен файл:

- задает поведение агента в этой папке проекта;
- не дает агенту фантазировать числа;
- напоминает, что расчеты выполняет инструмент;
- фиксирует правила безопасности по персональным данным.

Что важно проверить:

- агенту явно запрещено считать средние баллы и пропуски "в голове";
- есть требование вызвать MCP перед отчетом;
- есть правила работы с персональными данными;
- есть критерии группы риска.

### 3. `mcp/stat-collector/index.js`

Это локальный MCP-сервер.

В нем должен быть инструмент, например:

```text
analyze_group_stats
```

Важно объяснить:

> `analyze_group_stats` не обязательно будет отдельной функцией с таким именем. В MCP SDK инструмент часто регистрируется как объект с полем `name: 'analyze_group_stats'` в обработчике `ListToolsRequestSchema`, а затем вызывается через общий обработчик `CallToolRequestSchema`.

То есть в `index.js` участники могут увидеть не это:

```js
function analyze_group_stats(...) {
  ...
}
```

а такую структуру:

```js
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: 'analyze_group_stats',
      description: '...',
      inputSchema: { ... },
    },
  ],
}));

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name !== 'analyze_group_stats') {
    throw new Error(`Неизвестный инструмент: ${request.params.name}`);
  }

  // здесь выполняется чтение CSV и расчет показателей
});
```

Это нормальная структура MCP-сервера: имя инструмента объявляется отдельно, а логика вызова находится в обработчике запроса.

Что делает инструмент:

- принимает путь к CSV-файлу;
- читает `data/group_stats.csv`;
- считает количество студентов;
- считает средний балл по группе;
- суммирует пропуски;
- считает количество студентов с задолженностями;
- определяет группу риска по правилам;
- возвращает результат как структурированные данные.

Для чего нужен файл:

- выносит точные расчеты из LLM в код;
- делает результат проверяемым;
- превращает таблицу в инструмент агента;
- показывает смысл MCP: агент вызывает внешнюю функцию, а не просто рассуждает текстом.

Что важно проверить:

- инструмент не отправляет данные во внешние API;
- инструмент читает только указанный файл;
- критерии риска совпадают с `AGENTS.md`;
- результат содержит не только текст, но и структурированные данные: student_id, причины риска, суммарные показатели.

Важно:

> OpenCode может назвать главный файл MCP-сервера `index.js`, `server.js` или `server.mjs`. На скриншоте создан `index.js` - это нормальный вариант для маленького npm-пакета. Главное, чтобы команда запуска в `package.json` или `opencode.json` указывала на фактически созданный файл.

### 4. `mcp/stat-collector/package.json`, `package-lock.json`, `node_modules/`

Это служебные файлы npm-пакета MCP-сервера.

В `package.json` обычно описано:

- имя локального пакета;
- тип модулей, если используется современный JavaScript;
- команда запуска;
- зависимости, если они нужны.

`package-lock.json` фиксирует точные версии установленных зависимостей.

`node_modules/` содержит сами установленные npm-пакеты.

Для чего нужны эти файлы:

- помогает запускать MCP-сервер предсказуемо;
- фиксирует, какие зависимости нужны;
- делает папку `mcp/stat-collector/` самостоятельным маленьким инструментом.

Что важно проверить:

- нет лишних зависимостей;
- если зависимости есть, OpenCode объяснил, зачем они нужны;
- запуск сервера соответствует тому, что указано в `opencode.json`.
- `node_modules/` не редактируем руками;
- если проект передается другому человеку, обычно передают `index.js`, `package.json` и `package-lock.json`, а `node_modules/` можно восстановить командой `npm install`.

### 5. `opencode.json`

Это конфигурация проекта OpenCode.

В этой практике в нем нужно подключить MCP-сервер `stat-collector`.

В нем должно быть описано:

- имя MCP-сервера;
- что сервер локальный;
- команда запуска;
- рабочая папка или путь к серверу, если нужен.

В нем не обязательно должны быть описаны модели.

Куратор объясняет:

> `opencode.json` может быть частичным проектным конфигом. В этой практике он нужен только для подключения MCP-сервера. Модели и провайдеры уже могли быть настроены раньше через `/connect`, глобальную конфигурацию OpenCode, Ollama или сохраненные настройки пользователя.

Поэтому такой файл нормален:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "stat-collector": {
      "type": "local",
      "command": ["node", "mcp/stat-collector/index.js"],
      "enabled": true
    }
  }
}
```

Почему он запускается без блока моделей:

- OpenCode берет модель из уже выбранного провайдера;
- проектный `opencode.json` добавляет только то, что нужно конкретному проекту;
- MCP-инструмент не является моделью, это внешний инструмент;
- не нужно дублировать настройки моделей в каждом учебном проекте.

Когда модели стоит указывать отдельно:

- если занятие должно жестко использовать конкретную локальную модель;
- если проект переносится на компьютеры, где OpenCode еще не подключен к провайдеру;
- если нужно показать явную связку OpenCode + Ollama;
- если у группы несколько моделей и важно зафиксировать одну.

Важно: в OpenCode используется ключ `mcp`, а не `mcpServers`.

Правильный формат для OpenCode:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "stat-collector": {
      "type": "local",
      "command": ["node", "./mcp/stat-collector/index.js"],
      "enabled": true
    }
  }
}
```

Если MCP-сервер должен запускаться из своей папки, можно добавить `cwd`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "stat-collector": {
      "type": "local",
      "command": ["node", "index.js"],
      "cwd": "./mcp/stat-collector",
      "enabled": true
    }
  }
}
```

Неправильный для OpenCode формат:

```json
{
  "mcpServers": {
    "stat-collector": {
      "command": "node",
      "args": ["./mcp/stat-collector/index.js"]
    }
  }
}
```

`mcpServers`, `args`, `env`, `disabled`, `autoApprove` часто встречаются в конфигурациях других MCP-клиентов. OpenCode валидирует `opencode.json` по своей схеме и выдаст ошибку `Unrecognized key: mcpServers`.

Для чего нужен файл:

- сообщает OpenCode, какие MCP-инструменты доступны в проекте;
- связывает агента и локальный сервер расчетов;
- позволяет OpenCode вызвать `analyze_group_stats`.

Что важно проверить:

- MCP называется понятно, например `stat-collector`;
- верхний ключ называется `mcp`, а не `mcpServers`;
- `command` записан массивом, например `["node", "./mcp/stat-collector/index.js"]`;
- команда запуска указывает на созданный сервер;
- после перезапуска `opencode mcp list` показывает сервер;
- если сервер не запускается, ошибка понятна и ее можно диагностировать.

### 6. `outputs/report.md`

Это итоговый отчет для куратора.

Он может появиться не сразу, а после улучшения MCP или после отдельного запроса.

В нем должен быть:

- краткий обзор группы;
- средний балл;
- пропуски всего;
- неуважительные пропуски;
- количество студентов с задолженностями;
- список группы риска;
- причины попадания в группу риска;
- рекомендации куратора.

Для чего нужен файл:

- сохраняет результат работы агента;
- отделяет исходные данные от итогового отчета;
- дает куратору файл, который можно открыть, проверить и при необходимости доработать.

Что важно проверить:

- числа в отчете совпадают с результатом MCP;
- в отчете нет персональных данных;
- студентам группы риска указаны только `student_id`;
- рекомендации не содержат медицинских, юридических или дисциплинарных выводов без проверки человеком.

### Итоговая логика файлов

Куратор показывает цепочку:

## 0-10 мин. Вход в занятие

Куратор объясняет задачу:

> Сегодня мы делаем агента, который работает с таблицей. Но важное правило: агент не должен "на глаз" считать средние баллы и пропуски. Он должен вызвать инструмент, получить числа и только потом оформить отчет.

Показать разницу:

- без инструмента: LLM может ошибиться в арифметике;
- со скриптом: можно посчитать точно, но это отдельная команда;
- с MCP: инструмент становится частью рабочей среды агента.

Куратор задает группе вопрос:

> Какие показатели обычно вручную считают кураторы?

Примеры:

- средний балл;
- количество оценок `2`;
- количество пропусков;
- пропуски без уважительной причины;
- процент посещаемости;
- список должников;
- список группы риска;
- динамика по месяцу.

Создать структуру:

```bash
mkdir -p opencode-stat-collector/data opencode-stat-collector/mcp/stat-collector opencode-stat-collector/outputs
cd opencode-stat-collector
```

Назначение папок:

- `data/` - обезличенные таблицы;

## 18-28 мин. Создание учебных данных через OpenCode

Куратор не раздает готовую таблицу. Участники просят OpenCode создать маленький учебный CSV.

Запрос:

```text
Создай учебный обезличенный CSV-файл data/group_stats.csv для практики по коллектору статистики.

Требования:
- 12 студентов;
- вместо ФИО используй student_id: S001, S002 и т.д.;
- колонки:
  - student_id
  - group
  - avg_grade
  - failed_subjects
  - absences_total
  - absences_unexcused
  - assignments_missing
- данные должны быть синтетическими;
- добавь несколько студентов с риском: низкий средний балл, долги, много пропусков.

После создания файла кратко объясни, какие колонки в нем есть.
```

Если OpenCode только показывает CSV в чате:

```text
Не просто покажи таблицу. Создай файл data/group_stats.csv в проекте.
```

Куратор объясняет:

> Мы специально начинаем с маленького набора данных. Его можно проверить глазами. Если инструмент ошибется на 12 строках, на реальной ведомости ему доверять нельзя.

## 28-38 мин. Формулируем правила расчета

Попросить OpenCode создать проектную инструкцию:

```text
Создай AGENTS.md для проекта "Коллектор статистики".

Требования:
- агент помогает куратору анализировать обезличенную таблицу успеваемости и посещаемости;
- агент не должен считать показатели сам языковой моделью;
- для расчетов агент должен использовать MCP-инструмент stat-collector;
- агент может объяснять результат и оформлять отчет;
- агент не должен запрашивать ФИО, телефоны, адреса, медицинские сведения и другие персональные данные;
- если пользователь дает реальные персональные данные, агент должен попросить обезличить таблицу;
- группа риска определяется правилами:
  - avg_grade < 3.5;
  - или failed_subjects > 0;
  - или absences_unexcused >= 6;
  - или assignments_missing >= 3;
- итоговый отчет должен включать: сводку по группе, список группы риска, причины риска, рекомендации куратору.
```

Куратор поясняет:

> `AGENTS.md` здесь не считает. Он задает правила поведения агента и говорит: для чисел используй инструмент.

## 38-55 мин. Просим OpenCode создать MCP-инструмент

Куратор объясняет:

> MCP-сервер будет локальным. Он читает CSV, считает показатели и возвращает структурированный результат. Это полезнее, чем просить LLM считать таблицу в голове.

Запрос к OpenCode:

```text
Создай локальный MCP-сервер mcp/stat-collector.

Задача MCP:
- предоставить инструмент analyze_group_stats;
- инструмент принимает путь к CSV-файлу, например data/group_stats.csv;
- инструмент читает CSV;
- считает:
  - количество студентов;
  - средний avg_grade по группе;
  - суммарные absences_total;
  - суммарные absences_unexcused;
  - количество студентов с failed_subjects > 0;
  - список студентов группы риска;
- группа риска определяется так:
  - avg_grade < 3.5;
  - или failed_subjects > 0;
  - или absences_unexcused >= 6;
  - или assignments_missing >= 3;
- для каждого студента группы риска вернуть student_id и причины риска;
- результат вернуть как JSON и короткий markdown summary;
- не использовать внешние зависимости, если можно обойтись стандартным Node.js;
- не отправлять данные во внешние API.

Также создай или обнови opencode.json, чтобы OpenCode подключал этот локальный MCP-сервер.

Важно для opencode.json:
- используй ключ `"mcp"`, а не `"mcpServers"`;
- для локального сервера укажи `"type": "local"`;
- `"command"` должен быть массивом, например `["node", "./mcp/stat-collector/index.js"]`;
- не используй поля `args`, `env`, `disabled`, `autoApprove`, если они относятся к формату другого MCP-клиента;
- добавь `"$schema": "https://opencode.ai/config.json"`.
- не добавляй настройки моделей и провайдеров в этот файл: в этой практике opencode.json нужен только для подключения MCP.

Сначала объясни план, затем создай файлы.
```

Если OpenCode спрашивает про зависимости:

> Для учебной практики лучше минимальная реализация на Node.js без тяжелых зависимостей. Если MCP SDK необходим, агент должен явно объяснить, какая зависимость нужна и как ее установить.

## 55-62 мин. Проверка подключения MCP

Проверить список MCP:

```bash
opencode mcp list
```

Если сервер не виден или не запускается, попросить OpenCode:

```text
Проверь подключение MCP stat-collector.
Посмотри opencode.json, команду запуска MCP и ошибки.
Исправь минимально необходимое.
```

Если OpenCode показывает ошибку:

```text
Unrecognized key: mcpServers
```

значит `opencode.json` создан в формате другого MCP-клиента. Нужно заменить верхний ключ `mcpServers` на `mcp` и привести описание сервера к формату OpenCode:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "stat-collector": {
      "type": "local",
      "command": ["node", "./mcp/stat-collector/index.js"],
      "enabled": true
    }
  }
}
```

Куратор объясняет:

> На этом шаге не надо сразу чинить все вручную. Важно показать рабочий цикл: агент создал инструмент, мы проверили подключение, увидели ошибку, попросили агента диагностировать.

## Ключевой вывод

MCP полезен, когда агенту нужен устойчивый инструмент для работы с данными.

В этой практике:

- LLM понимает запрос и оформляет отчет;
- MCP читает таблицу и считает показатели;
- `AGENTS.md` задает правила безопасности и отчетности;
- куратор проверяет результат на маленьком наборе данных.

Именно здесь MCP выглядит естественно: без него агент был бы разговорным помощником, который рискует ошибиться в числах; с MCP он становится интерфейсом к проверяемому расчетному инструменту.
