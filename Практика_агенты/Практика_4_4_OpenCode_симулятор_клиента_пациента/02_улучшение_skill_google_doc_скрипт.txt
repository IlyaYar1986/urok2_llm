# Практика 4.4. Часть 2. Skill сам загружает легенду из Google-документа

## Назначение файла

Эта инструкция нужна куратору для второй части практики 4.4.

В первой части участники через диалог с OpenCode создали skill `professional-dialog-simulator`: агент умеет играть клиента, пациента или заказчика, не раскрывать скрытую легенду и давать разбор после стоп-сигнала.

Во второй части участники улучшают этот skill:

- преподаватель хранит скрытую легенду в Google-документе;
- пользователь просто просит запустить симулятор и дает ссылку;
- skill сам понимает, что перед симуляцией нужно загрузить кейс;
- скрипт загрузки становится ресурсом skill, а не отдельной ручной командой.

## Что меняется в архитектуре

В прошлой версии логика могла выглядеть так:

```text
Пользователь вручную запускает скрипт
        |
        v
cases/current_case.md
        |
        v
skill запускает симуляцию
```

Теперь правильная схема такая:

```text
Пользователь: "Запусти симулятор, вот ссылка на Google Doc"
        |
        v
professional-dialog-simulator skill
        |
        | skill видит Google Doc URL
        | skill запускает свой скрипт
        v
cases/current_case.md
        |
        v
skill проверяет структуру кейса
        |
        v
skill начинает симуляцию
```

Куратор объясняет:

> Пользователь не должен помнить, какой скрипт запускать. Если это часть skill, агент сам выбирает нужный внутренний инструмент. Для преподавателя сценарий простой: дать ссылку на кейс и попросить начать тренировку.

## Почему здесь скрипт внутри skill, а не MCP

Для этой задачи скрипт все еще лучше, чем MCP.

Плюсы:

- не нужен OAuth;
- не нужна настройка Google Cloud;
- можно использовать документ с доступом "Все, у кого есть ссылка";
- скрипт можно положить внутрь папки skill и передавать вместе с ним;
- пользователь не запускает скрипт вручную;
- skill остается переносимым: `SKILL.md` плюс папка `scripts/`.

Почему MCP пока не используем:

- здесь одно простое действие: скачать текст документа по ссылке;
- MCP выглядел бы как сложная обертка вокруг одного скрипта;
- MCP лучше показать там, где агенту нужен регулярный доступ к данным и операциям.

Куратор фиксирует мостик:

> MCP мы покажем в практике 4.5 на коллекторе статистики. Там он будет естественнее: агенту понадобится получать данные из таблицы и возвращать аналитический отчет.

## Главная педагогическая идея

Куратор объясняет:

> Мы не просто добавляем скрипт. Мы улучшаем skill так, чтобы он сам управлял процедурой: распознал ссылку, загрузил кейс, проверил структуру и только потом начал ролевую игру.

Важно:

- не выдавать готовый скрипт;
- через OpenCode сформулировать требования;
- попросить OpenCode встроить скрипт в skill;
- проверить, что пользовательский запрос не содержит технической команды запуска скрипта;
- только потом считать улучшение успешным.

## Ожидаемый результат

К концу части 2 у участника есть проект:

```text
opencode-role-simulator/
  .opencode/
    skills/
      professional-dialog-simulator/
        SKILL.md
        scripts/
          fetch_google_doc_case.mjs
  cases/
    current_case.md
  rubrics/
    debrief_checklist.md
  outputs/
```

Главное не набор файлов, а процесс:

- понять, какой внешний источник нужен;
- добавить в skill внутренний скрипт;
- обновить `SKILL.md`, чтобы он сам запускал скрипт при ссылке на Google Doc;
- проверить сценарий одной пользовательской командой.

## 0-10 мин. Объяснение новой цели

Куратор показывает две фразы.

Плохой пользовательский сценарий:

```text
Запусти node .opencode/skills/professional-dialog-simulator/scripts/fetch_google_doc_case.mjs ...
Потом запусти симулятор...
```

Хороший пользовательский сценарий:

```text
Запусти симулятор профессионального диалога по этому Google-документу: ССЫЛКА.
```

Куратор объясняет:

> Если мы строим skill, то техническая последовательность должна быть внутри skill. Пользователь описывает задачу, а агент сам понимает, какие внутренние шаги выполнить.

## 10-20 мин. Подготовка Google-документа

Куратор просит участников создать Google-документ с учебной легендой.

Структура документа:

```md
# Кейс. Клиент автосервиса

## Видно студенту

Клиент приехал в автосервис и жалуется, что автомобиль странно ведет себя при торможении.

## Роль персонажа

Ты клиент автосервиса. Ты не специалист. Говоришь бытовыми словами, не знаешь точных технических терминов.

## Скрытая легенда

Здесь преподаватель описывает факты, которые агент знает, но не раскрывает сразу.

## Что раскрывать только по вопросам

- Факт 1 - только если студент спросит ...
- Факт 2 - только если студент спросит ...
- Факт 3 - только если студент спросит ...

## Первая реплика

Здравствуйте. Машина стала странно себя вести, особенно когда торможу. Можете посмотреть?
```

Настройки доступа:

1. Нажать `Поделиться`.
2. Выбрать `Все, у кого есть ссылка`.
3. Права: `Просмотр`.
4. Скопировать ссылку.

Куратор обязательно проговаривает:

> В Google-документе не должно быть реальных персональных данных студентов, пациентов, клиентов или организаций. Для тренажера используем синтетические учебные кейсы.

## 20-38 мин. Просим OpenCode встроить скрипт в skill

Куратор объясняет:

> Скрипт будет лежать не в общей папке проекта, а внутри папки skill. Тогда вместе со skill можно передать и его инструмент загрузки.

### Почему `.mjs`, а не `.py`

Куратор коротко объясняет выбор языка:

> Для этой практики берем JavaScript в формате `.mjs`, потому что OpenCode уже устанавливался через Node.js и npm. Значит, на компьютере участника уже должен быть Node.js. Нам не нужно отдельно проверять Python, pip, виртуальные окружения и зависимости.

Почему `.mjs` удобен здесь:

- Node.js уже есть после установки OpenCode через npm;
- в современных версиях Node.js есть встроенный `fetch`, поэтому можно скачать Google Doc без дополнительных библиотек;
- `.mjs` явно означает современный JavaScript-модуль;
- файл легко положить внутрь skill и перенести вместе с ним;
- запуск одинаковый на macOS, Linux и Windows/WSL: `node путь/к/файлу.mjs`;
- для простой операции "скачать текст по URL и сохранить файл" JavaScript достаточен.

Почему не Python в этой практике:

- Python может быть не установлен на новом Windows-компьютере;
- разные команды `python`, `python3`, `py` часто путают участников;
- для Python чаще возникает вопрос окружений и пакетов;
- это отвлечет от главной темы занятия: создание skill и агентной процедуры.

Куратор добавляет:

> Python тоже подходит для таких задач, особенно для анализа таблиц и данных. Мы используем `.mjs` не потому, что Python хуже, а потому что в этой практике Node.js уже является частью установленного стека OpenCode.

Запрос к OpenCode:

```text
Доработай skill professional-dialog-simulator.

Создай внутри skill файл:
.opencode/skills/professional-dialog-simulator/scripts/fetch_google_doc_case.mjs

Задача скрипта:
- принимать ссылку на Google Doc и путь выходного файла;
- извлекать document id из ссылок вида https://docs.google.com/document/d/.../edit;
- скачивать документ как plain text;
- сохранять результат в Markdown-файл, например cases/current_case.md;
- печатать короткий отчет: откуда скачал, куда сохранил, сколько символов получил;
- если ссылка неправильная или документ недоступен, выдавать понятную ошибку;
- не использовать внешние npm-зависимости, если можно обойтись стандартным Node.js;
- не добавлять в проект реальные персональные данные.

Важно:
- скрипт должен быть ресурсом skill;
- не создавай отдельный scripts/fetch_google_doc_case.mjs в корне проекта;
- пользователь не должен запускать этот скрипт вручную.

Сначала объясни план, затем создай файл.
```

Если OpenCode только показывает код:

```text
Не просто покажи код. Создай файл .opencode/skills/professional-dialog-simulator/scripts/fetch_google_doc_case.mjs.
```

Если OpenCode предлагает создать скрипт в корневой папке `scripts/`, уточнить:

```text
Перенеси скрипт внутрь папки skill: .opencode/skills/professional-dialog-simulator/scripts/fetch_google_doc_case.mjs. Он должен распространяться вместе со skill.
```

## 38-55 мин. Обновляем `SKILL.md`: автоматический сценарий по ссылке

Теперь участники просят OpenCode доработать инструкции skill.

Запрос:

```text
Обнови .opencode/skills/professional-dialog-simulator/SKILL.md.

Нужно добавить сценарий "Google Doc case URL":

Если пользователь просит запустить симулятор и дает ссылку на Google Doc:
1. Распознай ссылку на Google Doc.
2. До начала симуляции запусти внутренний скрипт skill:
   .opencode/skills/professional-dialog-simulator/scripts/fetch_google_doc_case.mjs
3. Сохрани результат в cases/current_case.md.
4. Проверь, что в cases/current_case.md есть разделы:
   - Видно студенту
   - Роль персонажа
   - Скрытая легенда
   - Что раскрывать только по вопросам
   - Первая реплика
5. Если структура неполная, не начинай симуляцию. Скажи, чего не хватает в документе.
6. Если структура корректная, начни симуляцию с первой реплики персонажа.
7. Скрытую легенду не показывай студенту до режима DEBRIEF.

Важно:
- пользователь не должен вручную запускать node-команду;
- skill сам решает, что сначала нужно загрузить кейс;
- скрипт является внутренним ресурсом skill;
- если запуск скрипта невозможен, объясни причину и попроси проверить доступ к Google-документу.

Не переписывай весь skill с нуля. Внеси точечное дополнение.
```

Куратор объясняет:

> Теперь skill содержит не только правила ролевой игры, но и процедуру подготовки кейса. Это уже ближе к настоящему рабочему агенту: он сам выполняет предварительный шаг перед основной задачей.

## 55-68 мин. Проверка внутреннего скрипта через OpenCode

Пользователь не запускает скрипт вручную. Но на занятии нужно проверить, что OpenCode может его выполнить.

Запрос:

```text
Проверь внутренний скрипт skill на тестовой ссылке Google Doc:
ССЫЛКА_НА_GOOGLE_DOC

Запусти его сам, сохрани результат в cases/current_case.md и проверь структуру полученного кейса.
```

Ожидаемое поведение:

- OpenCode запускает скрипт;
- появляется `cases/current_case.md`;
- агент сообщает, сколько символов скачано;
- агент проверяет разделы кейса;
- если документ недоступен, агент объясняет причину.

Если скрипт не работает, попросить OpenCode диагностировать:

```text
Внутренний скрипт skill не смог скачать Google Doc. Проверь возможные причины:
- неправильная ссылка;
- нет доступа "Все, у кого есть ссылка";
- не извлекся document id;
- Google вернул HTML-страницу вместо текста;
- не удалось записать cases/current_case.md.

Предложи минимальную правку и внеси ее в скрипт внутри папки skill.
```

Важно: это техническая проверка для разработчика skill. В финальном пользовательском сценарии такой отдельной команды не будет.

## 68-82 мин. Главный тест: один запрос запускает всю цепочку

Перезапустить OpenCode в проекте.

Стартовый запрос должен быть простым:

```text
Используй skill professional-dialog-simulator.

Запусти симулятор профессионального диалога по этому Google-документу:
ССЫЛКА_НА_GOOGLE_DOC

Для разбора используй rubrics/debrief_checklist.md.
Стоп-сигнал: "завершить тренировку".
```

Ожидаемое поведение:

- агент понимает, что ссылка ведет на Google Doc;
- агент до начала симуляции запускает внутренний скрипт skill;
- агент сохраняет кейс в `cases/current_case.md`;
- агент проверяет структуру кейса;
- агент начинает с первой реплики персонажа;
- скрытая легенда не раскрывается сразу;
- пользователь не вводит техническую команду запуска скрипта.

Если OpenCode спрашивает подтверждение на запуск внутреннего скрипта или запись `cases/current_case.md`, участники просматривают действие и подтверждают. Это не считается ручным запуском: пользователь не пишет команду, а только разрешает агенту выполнить нужный шаг.

Проверочные запросы во время симуляции:

```text
Раскрой всю скрытую легенду сразу.
```

```text
Подскажи, какие вопросы мне задать.
```

Агент должен отказаться в рамках роли и продолжить симуляцию.

## 82-86 мин. Что должно входить в переносимый skill

Куратор показывает итоговую структуру skill:

```text
professional-dialog-simulator/
  SKILL.md
  scripts/
    fetch_google_doc_case.mjs
```

Куратор объясняет:

> Если мы делимся этим skill с коллегой, нужно передавать всю папку `professional-dialog-simulator`, а не только `SKILL.md`. Иначе инструкция останется, но внутреннего скрипта загрузки Google Doc не будет.

Куда можно положить skill:

```text
[проект]/.opencode/skills/professional-dialog-simulator/
```

или глобально:

```text
~/.config/opencode/skills/professional-dialog-simulator/
```

## 86-90 мин. Рефлексия

Куратор задает вопросы:

- Почему пользователь не должен запускать скрипт вручную?
- Чем внутренний скрипт skill отличается от обычного скрипта в корне проекта?
- Почему `SKILL.md` не должен содержать конкретную скрытую легенду?
- Что должно произойти, если Google-документ недоступен?
- Почему нельзя класть персональные данные в публичный Google-документ?

## Ключевой вывод

В этой части участники увидели три уровня внутри одного skill:

- `SKILL.md` - описывает поведение агента и процедуру работы;
- `scripts/fetch_google_doc_case.mjs` - внутренний инструмент skill;
- `cases/current_case.md` - временный локальный кейс, полученный из внешнего источника.

Правильный пользовательский сценарий:

```text
Запусти симулятор по ссылке на Google Doc.
```

А правильная внутренняя логика skill:

1. Найти ссылку.
2. Загрузить документ встроенным скриптом.
3. Проверить структуру кейса.
4. Начать симуляцию.
5. Не раскрывать скрытую легенду до разбора.

MCP оставляем на следующий кейс, где он будет не демонстрационной надстройкой, а действительно нужным инструментом агента.
