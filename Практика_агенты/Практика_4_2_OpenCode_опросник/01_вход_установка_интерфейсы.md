# Практика 4.2. OpenCode: вход, установка и интерфейсы

## Назначение файла

Эта инструкция нужна куратору для первой части практического занятия. В этом блоке участники понимают, что такое OpenCode, где его взять, как установить и в каких интерфейсах с ним можно работать.

Создание агента в этом файле не разбирается. Оно вынесено в отдельную инструкцию.

## 0-10 мин. Вход в занятие

Куратор объясняет:

OpenCode здесь используется не как "программа для программистов", а как готовая оболочка для сборки локальных рабочих агентов.

Агент будет жить в папке проекта, иметь инструкции, skills и при необходимости доступ к файлам или скриптам.

Главная идея занятия:

- мы не пишем полноценное приложение;
- мы собираем управляемого помощника с понятной ролью;
- его поведение задается инструкциями;
- позже к такому агенту можно подключать файлы, MCP и скрипты.

Что важно проговорить группе:

- OpenCode работает в контексте папки проекта;
- все материалы агента лучше хранить рядом с проектом;
- агент должен иметь четкую задачу и границы;
- чем конкретнее инструкция, тем надежнее результат.

Формулировка для куратора:

> Сегодня мы используем OpenCode как конструктор рабочих агентов. Первый агент будет простым: он проведет опрос по сценарию и соберет итоговую заявку. Нам важно понять базовый принцип: агент - это не один промпт, а настроенная рабочая роль с правилами поведения.

## 10-25 мин. Где взять и как установить

Куратор показывает сайт OpenCode:

```text
https://opencode.ai
```

Затем открыть страницу загрузки:

```text
https://opencode.ai/download
```

Показать, что OpenCode доступен в нескольких вариантах:

- терминальный OpenCode;
- OpenCode Desktop;
- расширения для VS Code, Cursor, Zed, Windsurf, VSCodium;
- интеграции с GitHub и GitLab.

### Основной вариант установки для практики: npm

Для занятия выбираем один основной способ установки терминального OpenCode:

```bash
npm install -g opencode-ai
```

Почему именно npm:

- один и тот же принцип работает на Windows, macOS и Linux;
- это официальный и понятный способ установки терминального OpenCode;
- через npm легко обновлять OpenCode;
- дальше на курсе нам все равно понадобятся Node.js/npm для части инструментов, MCP-серверов и скриптов;
- куратору проще сопровождать группу, когда все идут по одному сценарию.

Важно:

> npm - это менеджер пакетов, который устанавливается вместе с Node.js. Если компьютер новый и на нем ничего нет, сначала ставим Node.js, потом через npm ставим OpenCode.

### Установка на новый компьютер: пошагово

#### Шаг 1. Установить Node.js

Открыть официальный сайт:

```text
https://nodejs.org
```

Скачать версию **LTS**.

Что объяснить участникам:

- LTS - стабильная версия для обычной работы;
- вместе с Node.js установится npm;
- отдельный npm скачивать не нужно.

Дальше установить Node.js обычным установщиком:

- на Windows - скачать `.msi`, открыть и пройти мастер установки;
- на macOS - скачать `.pkg`, открыть и пройти мастер установки;
- на Linux - лучше заранее подготовить установку под конкретный дистрибутив или использовать компьютер куратора для демонстрации.

Для учебной аудитории лучше установить Node.js заранее, чтобы не тратить время занятия на системную настройку.

#### Шаг 2. Закрыть и заново открыть терминал

После установки Node.js нужно закрыть терминал и открыть его снова.

Это важно, потому что система должна обновить пути к командам `node` и `npm`.

На Windows открыть:

```text
PowerShell
```

На macOS открыть:

```text
Terminal
```

На Linux открыть обычный терминал.

#### Шаг 3. Проверить Node.js и npm

Выполнить:

```bash
node --version
npm --version
```

Если обе команды показывают версии, можно ставить OpenCode.

Пример нормального результата:

```text
v22.0.0
10.0.0
```

Версии могут отличаться. Главное, чтобы команды сработали без ошибки.

Если команда `node` или `npm` не найдена:

- закрыть и заново открыть терминал;
- проверить, завершилась ли установка Node.js;
- на Windows попробовать открыть PowerShell от имени обычного пользователя, не из старого окна;
- если не помогло, перезагрузить компьютер.

#### Шаг 4. Установить OpenCode через npm

Выполнить:

```bash
npm install -g opencode-ai
```

Что означает команда:

- `npm` запускает менеджер пакетов;
- `install` означает установить пакет;
- `-g` означает глобальную установку, чтобы команда `opencode` была доступна из любого проекта;
- `opencode-ai` - пакет OpenCode.

#### Шаг 5. Проверить OpenCode

Выполнить:

```bash
opencode --version
```

Если версия отображается, терминальный OpenCode установлен.

#### Шаг 6. Первый запуск

Создать учебную папку:

```bash
mkdir opencode-survey-practice
cd opencode-survey-practice
opencode
```

Внутри OpenCode показать команды:

```text
/connect
/init
```

Что объяснить:

- `/connect` нужен для подключения провайдера модели;
- `/init` подготавливает текущую папку проекта к работе с OpenCode.

### Возможные проблемы при npm-установке

#### Команда `npm` не найдена

Причина: Node.js не установлен или терминал открыт до установки.

Что сделать:

1. Установить Node.js LTS с `https://nodejs.org`.
2. Закрыть терминал.
3. Открыть терминал заново.
4. Проверить `node --version` и `npm --version`.

#### Команда `opencode` не найдена после установки

Причина: глобальная npm-папка не попала в PATH.

Что сделать:

1. Закрыть и заново открыть терминал.
2. Проверить:

```bash
npm list -g --depth=0
```

3. Если `opencode-ai` есть в списке, но `opencode` не запускается, перезагрузить компьютер.
4. Если проблема остается, куратор фиксирует это как техническую проблему PATH и показывает работу на своем компьютере.

#### Ошибка прав доступа

Иногда глобальная установка через `npm install -g` требует прав на запись в системную папку.

Что сделать:

- на личном компьютере участника можно повторить установку с правами администратора;
- на учебном компьютере лучше не тратить время занятия и использовать заранее подготовленное рабочее место;
- на macOS и Linux не рекомендуется без необходимости начинать занятие с команд `sudo`, потому что это усложняет объяснение.

### Плюсы и минусы npm-варианта

Плюсы:

- единый сценарий для разных ОС;
- участники знакомятся с Node.js/npm, которые пригодятся дальше;
- установка OpenCode выполняется одной командой после установки Node.js;
- проще объяснять обновления и повторную установку;
- хорошо сочетается с VS Code и проектной папкой.

Минусы:

- на новом компьютере сначала нужно установить Node.js;
- на части компьютеров возможны проблемы с PATH;
- глобальная установка может упереться в права доступа;
- для совсем неподготовленной аудитории терминал может быть психологически сложнее, чем обычный установщик.

Когда использовать npm:

- как основной способ на этой практике;
- если участники будут работать с файлами проекта и VS Code;
- если дальше планируются skills, MCP, скрипты и локальные инструменты;
- если нужно одинаково объяснить установку для Windows, macOS и Linux.

Когда не использовать npm:

- если у участника нет прав на установку Node.js;
- если компьютер заблокирован политиками организации;
- если задача - только посмотреть визуальный интерфейс без настройки агента.

### Дополнительный вариант: OpenCode Desktop

OpenCode Desktop оставляем как отдельный визуальный вариант.

Его не устанавливаем через npm. Он скачивается с сайта OpenCode как обычная программа:

```text
https://opencode.ai/download
```

На странице Download выбрать OpenCode Desktop под свою ОС:

- macOS Apple Silicon;
- macOS Intel;
- Windows x64;
- Linux `.deb`;
- Linux `.rpm`.

Плюсы Desktop:

- привычная установка через обычный установщик;
- проще для участников, которым сложно начинать с терминала;
- удобно показать проекты и сессии визуально;
- подходит для обзорной демонстрации.

Минусы Desktop:

- desktop-версия находится в beta;
- для настройки агента все равно важно понимать, где лежат файлы проекта;
- при работе со skills, MCP и скриптами терминал все равно понадобится;
- инструкция по созданию агента в следующем файле ориентирована на проектную папку и терминальный запуск.

Когда использовать Desktop:

- чтобы показать, что у OpenCode есть не только терминальный интерфейс;
- если участнику нужно сначала освоиться визуально;
- как запасной путь для знакомства с OpenCode.

Когда не использовать Desktop как основной путь:

- если цель занятия - научиться создавать агента через файлы `.opencode`;
- если дальше планируется работа со скриптами и MCP;
- если куратор хочет, чтобы вся группа шла по одному техническому сценарию.

### Как подключить локальную LLM

Для локальной модели используем Ollama. Это отдельная программа, которая запускает LLM на компьютере участника и дает OpenCode локальный API.

Главная идея для куратора:

> OpenCode - это оболочка агента. Ollama - это место, где локально работает модель. Мы соединяем их через локальный адрес `http://localhost:11434/v1`.

#### Когда локальная LLM уместна

Использовать локальную модель стоит, если:

- нет стабильного доступа к облачным моделям;
- нельзя отправлять данные во внешние сервисы;
- нужно показать принцип работы полностью локального агента;
- задача не требует очень сильной модели.

Для первой практики с агентом-опросником локальной модели обычно достаточно: агент ведет простой диалог, задает уточняющие вопросы и оформляет итоговую заявку.

#### Ограничения локальной LLM

Важно заранее проговорить:

- локальная модель работает медленнее облачной;
- качество зависит от размера модели и мощности компьютера;
- маленькие модели хуже держат длинные инструкции;
- для сложных агентных задач OpenCode рекомендует модели с большим контекстом, желательно от 64k токенов;
- если компьютер слабый, лучше показывать локальную модель на машине куратора.

#### Шаг 1. Установить Ollama

Открыть сайт:

```text
https://ollama.com/download
```

Скачать установщик под свою ОС и установить Ollama обычным способом.

После установки проверить в терминале:

```bash
ollama --version
```

Если команда работает, Ollama установлен.

#### Шаг 2. Скачать локальную модель

Для учебной демонстрации можно взять небольшую универсальную модель:

```bash
ollama pull qwen3:8b
```

Если компьютер слабый, куратор может выбрать модель меньше. Если компьютер мощный, можно выбрать модель больше. Главное, чтобы название модели совпадало с тем, что потом будет указано в настройках OpenCode.

Проверить запуск модели:

```bash
ollama run qwen3:8b
```

В появившемся чате написать короткий запрос:

```text
Привет. Ответь одним предложением.
```

Чтобы выйти из чата Ollama:

```text
/bye
```

#### Шаг 3. Быстро запустить OpenCode через Ollama

У Ollama есть готовая интеграция с OpenCode:

```bash
ollama launch opencode
```

Эта команда запускает OpenCode с конфигурацией Ollama.

Если нужно только подготовить конфигурацию без запуска:

```bash
ollama launch opencode --config
```

Для первого показа куратору удобнее начать именно с:

```bash
ollama launch opencode
```

#### Шаг 4. Ручной вариант через `opencode.json`

Если нужно явно показать, как OpenCode подключается к локальной модели, создать в папке проекта файл:

```text
opencode.json
```

Вставить:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "qwen3:8b": {
          "name": "Qwen3 8B (local)",
          "limit": {
            "context": 65536,
            "output": 8192
          }
        }
      }
    }
  },
  "model": "ollama/qwen3:8b"
}
```

Что объяснить:

- `provider.ollama` - локальный провайдер модели;
- `baseURL` - адрес локального сервера Ollama;
- `models` - список моделей, которые OpenCode должен показывать;
- `model` - модель по умолчанию для проекта;
- `ollama/qwen3:8b` читается как `провайдер/модель`.

После этого запустить OpenCode в этой же папке:

```bash
opencode
```

Внутри OpenCode выполнить:

```text
/models
```

В списке должна появиться модель Ollama.

#### Быстрая диагностика локальной модели

Если OpenCode не видит локальную модель:

1. Проверить, что Ollama запущен.
2. Проверить модель:

```bash
ollama list
```

3. Проверить, что модель действительно отвечает:

```bash
ollama run qwen3:8b "Ответь одним коротким предложением."
```

4. Проверить, что в `opencode.json` указан адрес:

```text
http://localhost:11434/v1
```

5. Проверить, что в `opencode.json` модель называется так же, как в `ollama list`.

### Команды OpenCode

Куратору полезно разделить команды на два типа:

- команды внутри OpenCode TUI - начинаются с `/`;
- команды терминала - начинаются с `opencode`.

Список терминальных команд ниже проверен по `opencode --help` для OpenCode `1.17.8`. Для TUI-команд ориентироваться нужно на `Ctrl+P` в установленной версии.

На первой практике участникам обязательно нужны только `opencode`, `/connect`, `/init`, `/models`, `/exit` и `Ctrl+P` для списка действий. Остальные команды можно показать как справочник.

Важно:

> `/help` не выполняет действие агента и не печатает длинный список команд в чате. В текущем интерфейсе OpenCode он открывает справочное окно. На нем написано, что полный список действий и команд открывается через `Ctrl+P`. Закрыть окно можно через `Enter` или `Esc`.

Еще одно важное уточнение:

> Slash-команды внутри TUI могут немного отличаться между версиями OpenCode. Поэтому на занятии не надо просить участников искать все команды из таблицы вручную. Актуальный список для установленной версии открывается через `Ctrl+P`.

#### Команды внутри OpenCode TUI

Эти команды вводятся уже после запуска:

```bash
opencode
```

| Команда | Что делает |
|---|---|
| `/connect` | Подключает провайдера модели и помогает добавить API-ключи. Для локальной Ollama-модели чаще используется конфиг или `ollama launch opencode`. |
| `/compact` | Сжимает текущую сессию, чтобы освободить контекст. Алиас: `/summarize`. |
| `/editor` | Открывает внешний редактор для набора длинного сообщения. Использует переменную окружения `EDITOR`. |
| `/exit` | Выходит из OpenCode. Алиасы: `/quit`, `/q`. |
| `/export` | Экспортирует текущий разговор в Markdown и открывает его во внешнем редакторе. |
| `/help` | Открывает справочное окно Help. Если нужен список доступных действий и команд, нажать `Ctrl+P`. |
| `/init` | Создает или обновляет `AGENTS.md` для текущего проекта. Это базовая команда подготовки папки к работе с агентом. |
| `/models` | Показывает доступные модели и позволяет выбрать модель. |
| `/new` | Начинает новую сессию. Алиас: `/clear`. |
| `/redo` | Возвращает последнее отмененное сообщение и связанные изменения файлов. Работает после `/undo`; для восстановления изменений нужен git-репозиторий. |
| `/sessions` | Показывает сессии и позволяет переключаться между ними. Алиасы: `/resume`, `/continue`. |
| `/share` | Создает ссылку для шаринга текущей сессии. Использовать только если в сессии нет чувствительных данных. |
| `/themes` | Показывает доступные темы интерфейса. |
| `/thinking` | Показывает или скрывает блоки рассуждения, если выбранная модель их поддерживает. Не включает reasoning у модели, а только управляет отображением. |
| `/undo` | Отменяет последнее сообщение, ответ агента и связанные изменения файлов. Для отката файлов нужен git-репозиторий. |
| `/unshare` | Отключает ранее опубликованный шаринг текущей сессии. |

Примечание по `/details`:

> В официальной документации OpenCode встречается команда `/details` для переключения подробностей выполнения инструментов. Но если участник не видит ее в `Ctrl+P` или она не срабатывает в установленной версии, не используем ее на занятии. Для практики 4.2 она не нужна.

Дополнительный синтаксис внутри TUI:

| Синтаксис | Что делает |
|---|---|
| `@имя_файла` | Добавляет файл из проекта в контекст сообщения. |
| `!команда` | Запускает shell-команду и добавляет ее вывод в разговор. Например: `!ls -la`. |

#### Команды терминала `opencode`

Эти команды вводятся в обычном терминале, до входа в TUI.

| Команда | Что делает |
|---|---|
| `opencode` | Запускает терминальный интерфейс OpenCode в текущей папке. |
| `opencode [project]` | Запускает OpenCode для указанной папки проекта. |
| `opencode --version` | Показывает версию OpenCode. |
| `opencode --help` | Показывает справку по CLI. |
| `opencode completion` | Генерирует скрипт автодополнения для shell. На практике не нужен, но есть в CLI. |
| `opencode agent create` | Создает нового агента через интерактивный мастер: описание, режим, права, модель. |
| `opencode agent list` | Показывает список доступных агентов. |
| `opencode attach [url]` | Подключает TUI к уже запущенному backend-серверу OpenCode. |
| `opencode providers login [url]` | Добавляет учетные данные провайдера модели. `auth` работает как алиас для `providers`. |
| `opencode providers list` или `opencode providers ls` | Показывает подключенных провайдеров. |
| `opencode providers logout [provider]` | Удаляет учетные данные провайдера. |
| `opencode github install` | Устанавливает GitHub-агента в репозиторий. Для этой практики не нужен. |
| `opencode github run` | Запускает GitHub-агента, обычно внутри GitHub Actions. |
| `opencode mcp add` | Добавляет MCP-сервер в конфигурацию. Пригодится в следующих практиках. |
| `opencode mcp list` или `opencode mcp ls` | Показывает настроенные MCP-серверы и их статус. |
| `opencode mcp auth [name]` | Авторизует OAuth-MCP-сервер. |
| `opencode mcp auth list` или `opencode mcp auth ls` | Показывает MCP-серверы, для которых доступна OAuth-авторизация. |
| `opencode mcp logout [name]` | Удаляет OAuth-учетные данные MCP-сервера. |
| `opencode mcp debug <name>` | Помогает диагностировать проблемы подключения MCP-сервера. |
| `opencode models [provider]` | Показывает модели настроенных провайдеров. Можно передать провайдера, например `opencode models ollama`. |
| `opencode models --refresh` | Обновляет кэш списка моделей. |
| `opencode run "текст запроса"` | Запускает OpenCode в неинтерактивном режиме: один запрос - один ответ. Удобно для скриптов. |
| `opencode serve` | Запускает headless-сервер OpenCode с HTTP API без TUI. |
| `opencode session list` | Показывает сохраненные сессии. |
| `opencode session delete <sessionID>` | Удаляет выбранную сессию. |
| `opencode stats` | Показывает статистику токенов и стоимости по сессиям. |
| `opencode export [sessionID]` | Экспортирует данные сессии в JSON. |
| `opencode import <file>` | Импортирует сессию из JSON-файла или ссылки OpenCode Share. |
| `opencode web` | Запускает сервер OpenCode с веб-интерфейсом. |
| `opencode acp` | Запускает ACP-сервер для клиентов, которые общаются через Agent Client Protocol. |
| `opencode plugin <module>` или `opencode plug <module>` | Устанавливает плагин и обновляет конфигурацию. |
| `opencode pr <number>` | Забирает GitHub PR-ветку, переключается на нее и запускает OpenCode. |
| `opencode db [query]` | Выполняет запрос к внутренней базе OpenCode. |
| `opencode db path` | Показывает путь к базе данных OpenCode. |
| `opencode debug [command]` | Набор инструментов для диагностики и отладки. |
| `opencode uninstall` | Удаляет OpenCode и связанные файлы. Осторожно: команда разрушительная. |
| `opencode upgrade [target]` | Обновляет OpenCode до последней или указанной версии. |

Что отдельно проговорить группе:

> В практиках мы не будем учить все команды наизусть. Нам нужны `opencode`, `/init`, `/models`, `Ctrl+P` для списка действий и позже `opencode mcp add`. `/help` открывает только справочное окно. Остальное - справочник для самостоятельной работы.

## 25-40 мин. Интерфейсы OpenCode

Куратор показывает три режима работы.

### 1. CLI/TUI

Это основной рабочий режим для практики.

Создать папку проекта:

```bash
mkdir opencode-survey-practice
cd opencode-survey-practice
opencode
```

Пояснение:

- команда `opencode` запускает терминальный интерфейс;
- OpenCode работает внутри текущей папки;
- все будущие инструкции агента будут лежать в этой папке.

Внутри OpenCode показать команды:

```text
/connect
/init
```

Что объяснить:

- `/connect` нужен для подключения провайдера модели;
- `/init` анализирует проект и создает базовые инструкции для работы OpenCode в этой папке.

### 2. VS Code

Куратор открывает ту же папку в VS Code.

Дальше:

1. Открыть встроенный терминал.
2. Выполнить:

```bash
opencode
```

3. Показать, что OpenCode можно использовать прямо рядом с файлами проекта.

Что проговорить:

> Для многих преподавателей VS Code удобен тем, что слева видны файлы агента, а снизу или сбоку открыт OpenCode. Так проще редактировать инструкции и сразу проверять поведение агента.

### 3. OpenCode Desktop

Куратор показывает Desktop-версию как отдельную оболочку.

Что показать:

- выбор проекта;
- запуск сессии;
- переключение между сессиями;
- общий принцип: это более визуальный способ работать с тем же агентным подходом.

Что проговорить:

> Desktop удобен для тех, кому непривычен терминал. Но для обучения настройке агентов нам все равно полезно понимать, какие файлы лежат в папке проекта и как они влияют на поведение агента.
