# 22. Симулятор пациента (сбор анамнеза)

> Из анкеты (медицинский профиль, расшифровано по смыслу): «Текстовый агент, направленный
> на работу моего предмета, который ведёт диалог: сбор анамнеза, разбор клинических
> ситуаций». Также из той же анкеты — работа с методическими рекомендациями при написании
> ВКР/КР (учтено в файле 02) и помощь с расписанием (файл 13).

## Описание

Ролевой агент-тренажёр для студентов медицинских специальностей СПО: играет пациента
с заданной легендой (жалобы, история болезни, характер — разговорчивый, скрытный,
тревожный). Студент-фельдшер или медсестра отрабатывает сбор анамнеза диалогом; в конце
агент выходит из роли и даёт разбор: какие обязательные вопросы заданы, какие упущены,
насколько корректна была коммуникация.

## Способ реализации

1. Банк клинических легенд — составляет преподаватель (диагноз, анамнез, психотип);
   агент строго держится легенды и не выдаёт того, о чём не спросили.
2. Скилл `patient-role`: правила ролевой устойчивости (не подсказывать, отвечать как
   обычный человек, без медицинской терминологии).
3. Скилл `debrief`: чек-лист сбора анамнеза по стандарту (жалобы → anamnesis morbi →
   anamnesis vitae → аллергоанамнез...) → отчёт «спрошено/упущено» с оценкой коммуникации.
4. Важно: агент играет пациента, а **не даёт медицинских советов** — диагнозы и лечение
   разбирает преподаватель.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | GigaChat или DeepSeek-V3 | Ролевой диалог — базовая способность; важна устойчивость в роли |
| Локальная | Qwen3-8B | Диалог по легенде тянет даже 8B; кабинету без интернета хватит ноутбука |

## Скиллы

- `patient-role` — правила отыгрыша легенды и границы роли
- `debrief` — чек-лист анамнеза и критерии оценки коммуникации
- `legend-builder` — помощник преподавателя для создания новых легенд

## MCP

- Не нужны: чисто разговорный агент. Опционально `filesystem` для банка легенд и
  сохранения протоколов тренировок.

## Почему агент нужен

Отработка анамнеза требует стандартизированных пациентов — живых актёров, которых в СПО нет.
Агент даёт каждому студенту неограниченную безопасную практику с немедленным разбором —
это лучший педагогический кейс всего списка: тренируется именно коммуникация, где LLM
сильны, а цена ошибки нулевая (пациент виртуальный). Международная практика (OSCE-тренажёры)
подтверждает подход.

## Почему агент может быть не нужен

Модель может выдать клинически недостоверную картину (несочетаемые симптомы), и студент
запомнит неверный паттерн — каждую легенду должен выверить преподаватель. Текстовый чат
не тренирует осмотр, пальпацию и невербальную коммуникацию — это дополнение к практике
с людьми, а не замена. Есть риск, что студенты начнут «обыгрывать» агента вместо освоения
методики.

## Оболочка

**Open WebUI** — лучший вариант: каждый студент в своём чате, преподаватель видит протоколы.
**Hermes подходит хорошо** — это редкий полностью разговорный агент без инструментов:
локальная модель + системный промпт с легендой, работает офлайн. opencode избыточен,
но удобен преподавателю для генерации банка легенд.
