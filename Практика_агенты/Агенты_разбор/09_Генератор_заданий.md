# 09. Генератор тестов и заданий

> Из анкет (6 анкет): «Разработка тестовых заданий с использованием критериев оценки,
> с использованием рабочей программы и ФГОС по специальности, строго по инструкции;
> разрабатывать задания по ситуационным задачам (ОП.01)», «Агент-генератор задач — создаёт
> практические задачи различного уровня», «ФОС-мастер», «Помощник — тесты», «РП → тесты».

## Описание

Агент генерирует контрольно-измерительные материалы по теме из рабочей программы: тестовые
вопросы разных типов (одиночный/множественный выбор, соответствие, открытый), ситуационные
задачи по профессии, практические задания трёх уровней сложности. К каждому заданию —
эталон ответа и критерии оценивания. Выгрузка в формат Moodle (GIFT) или печатный бланк.

## Способ реализации

1. Вход: тема + фрагмент РП + примеры заданий из существующего ФОС (для стиля).
2. Скилл `test-gen`: схема «вопрос → дистракторы → эталон → критерий»; обязательная проверка,
   что дистракторы правдоподобны, а правильный ответ не выделяется длиной.
3. Скилл `situational` — структура ситуационной задачи: условие из практики профессии →
   вопросы → эталонный разбор.
4. Самопроверка вторым прогоном: агент решает собственный тест «вслепую» и сверяет с эталоном —
   расхождение означает плохой вопрос. Отличный приём для занятия кружка.
5. Экспорт: GIFT для Moodle (большинство СПО на нём) или docx.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | DeepSeek-V3 | Массовая генерация дёшево; для сложных ситуационных задач — DeepSeek-R1 |
| Локальная | Qwen3-14B | Дистракторы — слабое место малых моделей; 8B даёт слишком очевидные варианты |

## Скиллы

- `test-gen` — типы вопросов, правила дистракторов, формат GIFT
- `situational` — шаблон ситуационной задачи по профессии
- `self-check` — протокол самопроверки сгенерированного теста

## MCP

- `filesystem` — РП и ФОС на входе, банки заданий на выходе
- Moodle MCP / Web API — опционально, прямая загрузка вопросов в курс

## Почему агент нужен

Банк из 200 вопросов руками — недели работы; агентом с проверкой преподавателя — день.
Вариативность заданий растёт (у каждого студента свой вариант — списывать бессмысленно),
уровни сложности позволяют дифференцировать группу. Это та генеративная задача, где LLM
объективно сильны, а проверка человеком проста и быстра.

## Почему агент может быть не нужен

Сгенерированные тесты проверяют запоминание, а не компетенции — есть риск заполнить курс
сотнями поверхностных вопросов («тестовый мусор»). Модель может ошибаться в фактах
спецдисциплины, и неверный эталон ответа хуже отсутствия теста. По массовым дисциплинам
готовые банки заданий уже существуют.

## Оболочка

**opencode** — пакетная генерация в файлы, экспорт GIFT, самопроверка скриптом. Для разовой
генерации «10 вопросов по теме» хватит **Open WebUI** или даже **Hermes** с локальной моделью
(чистый текст, инструменты не нужны) — но без экспорта и самопроверки.
