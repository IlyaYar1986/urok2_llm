# 17. «Чаки» — трекер документов и воинского учёта

> Из анкет (2 анкеты): «Чаки — агент должен пофамильно отслеживать документы, которые забыли
> забрать при отпуске и получении дипломов (наименование документа, год выдачи, ФИО и т.д.)»,
> «Военкомат — создать базу данных по военкомату».

## Описание

Агент-архивариус: ведёт реестр документов студентов и выпускников (аттестаты, дипломы,
справки), отслеживает невостребованные («кто не забрал диплом 2023 года»), формирует
описи и уведомления. Второй модуль — воинский учёт: база приписных, повесток, отсрочек,
автоматические списки для сверки с военкоматом.

## Способ реализации

1. База в SQLite: таблицы «документ / ФИО / год / статус / дата выдачи».
2. LLM — естественно-языковой интерфейс к базе: «кто из выпуска-2024 не забрал диплом» →
   SQL → список; «оформи опись невостребованных за 5 лет» → документ по шаблону.
3. Скилл `uvedomlenie`: генерация официальных писем выпускникам о необходимости забрать
   документы.
4. Напоминания по регламенту (сроки хранения, сверки с военкоматом) — cron-задачи.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | — недопустимо | Воинский учёт и документы об образовании — максимально чувствительные ПДн |
| Локальная | Qwen3-8B (Ollama) — **единственный вариант** | NL→SQL и шаблонные письма — лёгкая задача |

## Скиллы

- `doc-registry` — схема реестра и типовые запросы
- `uvedomlenie` — шаблоны официальных писем и описей
- `voinskiy-uchet` — регламент сверок и формы списков (строго по нормативке колледжа)

## MCP

- `sqlite` — реестр
- `filesystem` — описи, письма
- Cron (n8n) — регламентные напоминания

## Почему агент нужен

Невостребованные документы и воинский учёт — зона персональной ответственности конкретных
сотрудников со строгими сроками: забытая сверка — реальный штраф. Реестр с NL-интерфейсом
снимает зависимость от «той самой тетрадки» секретаря. Генерация описей и уведомлений по
шаблону — честная экономия времени.

## Почему агент может быть не нужен

Это чистая CRUD-задача: Excel или простая база Access решают её десятилетиями без ИИ —
LLM здесь лишь удобный, но необязательный интерфейс. Цена ошибки в воинском учёте высока,
а галлюцинация в списке для военкомата недопустима в принципе — каждый вывод агента всё
равно перепроверяется человеком, что съедает выгоду. Для кружка со школьниками работа
с такими данными вообще закрыта — только на синтетических данных.

## Оболочка

**opencode** с локальной моделью (SQLite MCP, файлы, скрипты). Регламентные напоминания —
**n8n**. Hermes не подходит: без доступа к базе агент бессмыслен. В кружке проект делается
строго на выдуманном датасете.
