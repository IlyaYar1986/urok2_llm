# 19. Визуализатор архитектуры компьютера

> Из анкет (2 анкеты): «Агент по архитектуре компьютера — 3D-визуализация компонентов,
> объяснение принятых компоновочных решений различных архитектур», «Практик — создавать
> визуализацию в схемах».

## Описание

Агент-объяснитель для дисциплины «Архитектура аппаратных средств»: по запросу строит схемы
(блок-схемы шин, тракт данных процессора, иерархия памяти) и объясняет компоновочные решения
(«почему кэш L1 разделён на инструкции и данные»). Визуализация — через Mermaid/SVG/
интерактивный HTML, который агент генерирует кодом; «честное 3D» — через готовые
three.js-шаблоны.

## Способ реализации

1. Скилл `scheme-gen`: типовые виды схем дисциплины + правила Mermaid (graph, flowchart)
   и SVG для трактов данных.
2. Скилл `explain`: формат «схема → пошаговое объяснение → вопрос на самопроверку».
3. Интерактив: агент собирает одностраничный HTML с анимацией прохождения команды по
   конвейеру (готовый каркас three.js/canvas, агент меняет параметры) — зрелищный
   результат для кружка.
4. Банк сцен пополняется по темам КТП дисциплины.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | DeepSeek-V3 | Генерация Mermaid/SVG/JS-кода — сильная сторона; дёшево для итераций |
| Локальная | Qwen3-14B (или Qwen2.5-Coder-7B) | Кодогенерация схем локально; 8B-кодер тоже справится |

## Скиллы

- `scheme-gen` — каталог схем дисциплины + правила Mermaid/SVG
- `explain` — педагогический формат объяснения по схеме
- `interactive-html` — каркасы анимаций (конвейер, кэш, прерывания)

## MCP

- `filesystem` — сохранение схем и HTML
- Playwright MCP — скриншоты готовых схем для презентаций (опционально)

## Почему агент нужен

Архитектура ПК — абстрактная дисциплина, где всё решает визуализация, а готовых хороших
анимаций на русском мало. Агент генерирует схему под конкретный вопрос студента, а не
«какая была в учебнике». Для кружка идеален: результат визуальный, тема — про сам компьютер,
кодогенерация демонстрируется наглядно.

## Почему агент может быть не нужен

Схемы из LLM содержат фактические ошибки (направления шин, размеры кэшей), которые студент
не распознает — каждую схему должен проверить преподаватель. Качественные симуляторы уже
существуют (Logisim, CPUlator, маркетплейсы анимаций) — возможно, лучше курировать готовое.
«3D-визуализация» в полном смысле — задача за пределами LLM-агента.

## Оболочка

**opencode** — генерация кода и файлов, просмотр результата в браузере. Hermes частично
подходит для текстовых объяснений с Mermaid-блоками (если рендерить их отдельно), но
интерактив через него не собрать. Open WebUI умеет рендерить Mermaid в чате — хороший
компромисс для студентов.
