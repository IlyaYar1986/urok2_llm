# 13. Составитель расписания

> Из анкет (5 анкет): «Агент, который составит расписание на учебный год — со всеми часами
> по группам, при необходимости замены с пересчётом всех остатков, разобьёт уроки так, чтобы
> не пересекались в течение дня», «Расписание — помощь в составлении расписания», «Агент по
> расписанию занятий — закинуть учебные планы, нагрузку преподавателей», «составление сетки
> расписаний», «расписание на спец. по учебному плану, по дням недели и часам».

## Описание

Агент-диспетчер: из учебных планов, нагрузки преподавателей и фонда аудиторий собирает
сетку расписания без конфликтов (преподаватель/группа/аудитория не пересекаются), считает
остатки часов и предлагает замены при больничных. Важно понимать: **LLM здесь — интерфейс,
а не решатель**. Само расписание строит алгоритм (солвер), LLM переводит пожелания на язык
ограничений и объясняет результат.

## Способ реализации

1. Данные: таблицы «дисциплина–группа–часы–преподаватель», аудитории, ограничения
   («у Ивановой нет первых пар», «спортзал только после обеда»).
2. Солвер: Google OR-Tools (CP-SAT) — школьникам даётся как готовый чёрный ящик с понятным
   входом; это сильное занятие про границы возможностей LLM.
3. LLM-агент: парсит пожелания в ограничения солвера → запускает → объясняет конфликты
   («невозможно: у группы 191 больше пар, чем слотов») → оформляет сетку в Excel.
4. Режим замен: «Петров на больничном до пятницы» → агент находит варианты замен с учётом
   нагрузки и квалификации.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | DeepSeek-V3 | Перевод пожеланий в ограничения и объяснение конфликтов — задача средней сложности |
| Локальная | Qwen3-14B | Расписание содержит ФИО преподавателей — локальный контур предпочтителен |

## Скиллы

- `constraints-parser` — перевод пожеланий на язык ограничений CP-SAT
- `solver-runner` — запуск OR-Tools и интерпретация результата
- `zamena` — протокол подбора замен с пересчётом остатков часов

## MCP

- `filesystem` + Excel/Google Sheets MCP — учебные планы и выгрузка сетки
- `sqlite` — хранение нагрузки и остатков часов

## Почему агент нужен

Составление расписания — каторжная комбинаторная работа завуча (недели в августе, хаос замен
весь год). Связка «LLM-интерфейс + солвер» реально решает задачу, а пересчёт остатков часов
при заменах — постоянная боль, которую агент снимает за секунды. Для кружка — лучший урок
о том, что LLM не всемогущи и сильны в связке с классическими алгоритмами.

## Почему агент может быть не нужен

Это самый сложный агент списка: без солвера LLM выдаст красивое расписание с конфликтами,
а с солвером проект выходит за рамки «агента» в полноценную систему. Готовые продукты
(«Экспресс-расписание», 1С:Колледж, ИС «Расписание») делают это профессионально, и колледж,
скорее всего, уже что-то использует. Ошибка в расписании парализует учебный процесс — цена
сбоя велика.

## Оболочка

**opencode** — единственный реалистичный вариант: нужен запуск Python-солвера, файлы, MCP.
Hermes и чат-оболочки непригодны принципиально. Для ежедневных замен поверх готовой сетки
можно собрать упрощённого Telegram-бота через n8n.
