# 23. Инструктор практических работ

> Из анкеты: «Инструктор — создание и контроль пошагового выполнения заданий: классной
> работы, практической, лабораторной. Отчёт о результатах выполнения задания, оценка».

## Описание

Агент ведёт студента по практической работе шаг за шагом: выдаёт следующий шаг только после
подтверждения предыдущего (фото результата, ответ на контрольный вопрос, вставленный
скриншот), отвечает на вопросы по текущему шагу, фиксирует прохождение и собирает для
преподавателя отчёт: кто на каком шаге, где застряли, типичные затруднения.

## Способ реализации

1. Методичка практической → структурированный сценарий: шаги, контрольные вопросы,
   критерии «шаг засчитан».
2. Скилл `step-control`: не раскрывать следующие шаги заранее, не давать готовый результат,
   на вопрос отвечать подсказкой, а не решением (сократический режим).
3. Проверка шага: текстовый ответ — LLM по критерию; фото установки/экрана — vision-модель.
4. Журнал прохождения в SQLite → сводка преподавателю после пары.

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | DeepSeek-V3 (+ Qwen-VL для фото) | Диалоговое сопровождение — недорого даже на группу |
| Локальная | Qwen3-8B + Qwen2.5-VL-7B | Класс без интернета: оба умещаются на одном GPU-компьютере |

## Скиллы

- `step-control` — протокол выдачи шагов и сократических подсказок
- `step-check` — критерии засчитывания шага (текст/фото)
- `progress-report` — формат сводки по группе для преподавателя

## MCP

- `filesystem` — сценарии работ
- `sqlite` — журнал прохождения

## Почему агент нужен

На практической один преподаватель физически не успевает к 25 студентам — сильные скучают,
слабые стопорятся молча. Агент даёт каждому индивидуальный темп и моментальную помощь, а
преподавателю — карту затруднений в реальном времени, превращая его из «отвечателя на
одинаковые вопросы» в наставника для сложных случаев.

## Почему агент может быть не нужен

Жёсткая пошаговость убивает самостоятельность: студент перестаёт читать методичку целиком
и планировать работу — а это само по себе компетенция. Проверка шагов по фото ненадёжна
(подсунуть чужой скриншот тривиально). Подготовка сценария к каждой работе — заметный труд;
для редких практических проще провести вживую.

## Оболочка

**Open WebUI** — студентам нужен только чат с загрузкой фото; прохождение пишется через
функцию-пайплайн. Сборка сценариев преподавателем — **opencode**. Hermes подходит лишь
частично: текстовые шаги потянет, но без vision-проверки и журнала.
