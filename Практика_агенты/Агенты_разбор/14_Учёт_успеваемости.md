# 14. Учёт успеваемости и посещаемости

> Из анкет (9 анкет — второй по частоте запрос): «Помощник в подсчёте пропусков группы —
> по данным в Excel, по уважительной/неуважительной причине за период», «Подсчёт пропусков —
> по болезни, заявлению и без причины», «Отчёт — сводная ведомость по итогам месяца/семестра/
> года: средний балл, качество, % успеваемости, посещаемость», «Формирование ведомостей
> успеваемости, посещаемости», «Контроль посещаемости с заполнением сводной таблицы»,
> «посчитать успевающих и неуспевающих», «вести учёт успеваемости студентов», «заполнение
> ведомости, отчёта по итогам семестра, шаблон заявления».

## Описание

Агент-делопроизводитель куратора: берёт журналы/таблицы Excel с оценками и пропусками и
делает всю производную отчётность — сводные ведомости, подсчёт среднего балла, % качества
и успеваемости, разбивку пропусков по причинам за любой период, списки должников, готовые
отчёты по шаблонам колледжа. Запросы на естественном языке: «сводка по группе 21-ИС за
ноябрь» → готовый docx.

## Способ реализации

1. Честная архитектура: **считает pandas, а не LLM** — числа из языковой модели недопустимы
   в ведомостях. LLM разбирает запрос, вызывает скрипт, оформляет результат.
2. Скилл `vedomost`: словарь показателей колледжа (качество = доля «4» и «5» и т.д.) +
   соответствие шаблонам отчётов.
3. Скрипты: чтение Excel-журналов (openpyxl/pandas), расчёты, выгрузка в шаблон docx.
4. Расширение: ежемесячный автоматический отчёт по расписанию (n8n cron).

## Модели

| Вариант | Модель | Почему |
|---|---|---|
| API | — не рекомендуется для реальных данных | Оценки и пропуски с ФИО — персональные данные |
| Локальная | Qwen3-8B (Ollama) — **основной вариант** | Разбор запроса и вызов скрипта — лёгкая задача; вся математика в pandas |

## Скиллы

- `vedomost` — формулы показателей и шаблоны отчётов колледжа
- `excel-parser` — правила чтения журналов (форматы листов, объединённые ячейки)
- `dolzhniki` — регламент списков задолженностей

## MCP

- Excel MCP / `filesystem` — журналы и отчёты
- `sqlite` — если данные переведены из Excel в базу (правильный шаг проекта)

## Почему агент нужен

9 анкет из 25 — самая массовая боль после РП/УМК. Кураторы вручную пересчитывают одни и те же
проценты каждый месяц. Задача формализована на 100%, ошибки ручного подсчёта реальны,
а экономия — часы ежемесячно у каждого куратора. Для кружка — образцовый урок «LLM как
интерфейс к коду»: дети видят, почему модель не должна считать сама.

## Почему агент может быть не нужен

Это задача Excel, а не ИИ: грамотная сводная таблица или готовый шаблон с формулами решает
её без единого токена — LLM-обёртка может оказаться избыточным слоем. Во многих колледжах
уже есть электронный журнал (1С:Колледж, региональные ГИС) со встроенными отчётами.
Персональные данные требуют строго локального контура и дисциплины с логами.

## Оболочка

**opencode** с локальной моделью — разбор запросов, запуск pandas-скриптов, файлы.
Для регулярных отчётов «по первым числам» — **n8n** (cron → скрипт → отчёт на почту).
Hermes не подходит: без инструментов агент будет фантазировать числа.
